# Paper figures and later implementation changes

This reproduction distinguishes matching the reported numerical evidence
from asserting that every archived experiment implements every sentence of
the latest manuscript. The main prediction track, OpenML track and all 243
replacement checks agree with the current final EIDOS implementation.

An initial full run using only the current checkout found the following
actual disagreements. These were not floating-point tolerance effects:

| Study | Current checkout versus archived paper results |
|---|---|
| Recovery sweep | 176/200 candidate identities agree; 185/200 recovery flags agree; 24 semantic NRMSE values differ |
| Interval study | 99/125 interval rows have the same selected candidate; 96/125 coverage values agree; 93/125 width values agree |

The initial field-level comparison is preserved under
`validation/current_checkout_protocol_audit/`. It is not used by any runner.

## Recovery

The source snapshot retained in the project's final R2 delivery generated
the reported recovery sweep with cross-fitting on the combined **discovery
plus diagnosis** rows. Initial candidate fits use discovery only; diagnosis
RMSE and codelength break ties, and the final refit uses discovery plus
diagnosis. Verification, calibration and test rows remain outside construction.

The later current `scripts/run_eswa_e5_recovery.py` changed cross-fitting to
**discovery only**, added a diagnosis invariance hard gate and selected-structure
ridge-grid tuning. Those are substantive protocol changes. Replacing the
archived sweep with that code does not reproduce the complete reported curve,
even though the three first-seed illustrative formulas still agree.

`experiments/recovery.py` therefore contains the archived sweep implementation,
with an observation-only candidate ledger added. The later implementation is
retained as text in `current_recovery_protocol_source.py.txt` for inspection,
not run as an ablation. `study_source_provenance.json` identifies source hashes
and packaging-only changes. The package does not label pooled construction
cross-fitting as discovery-only cross-fitting.

## Intervals

The published interval statistics were generated by the earlier EIDOS core
retained with the same study. Subsequent changes include correcting the MMD
permutation calculation to reuse the observed random Fourier feature map;
the archived implementation uses seed `seed` for the observed statistic and
`seed+1` for the permuted statistics. This changes gate decisions in the
archived interval configuration and can change the selected model.

`experiments/interval_core/` preserves the original study's numerical code
under a separate namespace. It cannot change the final benchmark implementation
in `src/eidos/`. This path is an archival numerical replay of the paper's
interval evidence; it is not a claim that the older permutation calculation
is the later corrected statistical test.

## Interpretation

The default `all` run regenerates the reported EIDOS evidence using its actual
study-specific source snapshots. It does not rewrite paper values, broaden
numeric tolerances to hide protocol changes, or imply that archival replay
resolves the manuscript/code protocol disagreement. A future update of the
paper's protocol description or its two figures would be a separate scientific
revision. This requested package records the discrepancy without modifying
the user's latest paper.
